# Deploy version notes: 2026-11-08

**Audience:** every git2 lane (Dash, Console, Codeplane, CI) and their coding agents.
**Scope:** the gateway's Git route and TLS are built (git2#24, git2#25) and run in Compose.

**Canonical reference:** [docs/api/gateway.md](../../../api/gateway.md), [docs/api/compose.md](../../../api/compose.md).
The API docs are the source of truth; this note only summarizes the change.

**Breaking?** No.

---

## 🟢 NEW: Git over HTTPS through the gateway

- `git clone`, `fetch` and `push` work against `http(s)://<host>/<owner>/<repo>.git` with the git2 username and password. Only the owner, as agreed for v0.
- The gateway turns the path into the repository ID (git-svc `FindRepository`), sets `X-Git2-User-Id` and streams to `git-svc:9080`. git-svc never sees names or passwords.
- `401` with a Basic challenge for no or wrong credentials, `404` for another owner's or a missing repository, `405` for a wrong method, `429` after 30 failed sign-ins per IP or 100 per username in 10 minutes, `503` when the database or git-svc cannot answer.
- `GET /readyz` checks git2 core and git-svc.

## 🟢 NEW: TLS

- `docker compose -f compose.yaml -f compose.tls.yaml up -d`: HTTPS on `GIT2_HTTPS_PORT` (TLS 1.2+, HSTS), plain HTTP only redirects (`308`) to `GIT2_EXTERNAL_URL`.
- Needs `GIT2_EXTERNAL_URL` and `GIT2_TLS_DIR` (`fullchain.pem`, `privkey.pem`, readable by uid 65532).

## 🟢 NEW: `git2ctl install`

`git2ctl install --url https://<host> --tls-dir <dir> --with-git-svc` checks the host, writes `git2.yaml` with new secrets and starts the stack, then waits until git2 answers. Reference: [git2ctl.md](../../../api/git2ctl.md). `upgrade` follows in W4.

## 🟡 CHANGED: Compose gateway settings

The gateway now gets `POSTGRES_DSN` (to check Git passwords against auth-svc's users), `GIT_SVC_GRPC_ADDR` and `GIT_SVC_HTTP_URL`, and waits for `migrate`.
