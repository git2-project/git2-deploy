# Deploy version notes: 2026-11-06

**Audience:** every git2 lane (Dash, Console, Codeplane, CI) and their coding agents.
**Scope:** the gateway contract moves to v0.1, in line with auth-svc (git2#14, git2#18), git-svc Smart HTTP (git2-codeplane#5) and the dash-api contract (git2#17). The gateway itself is not built yet.

**Canonical reference:** [docs/api/gateway.md](../../../api/gateway.md).
The API docs are the source of truth; this note only summarizes the change.

**Breaking?** No. Nothing was built against v0 yet.

---

## 🟡 CHANGED: who checks what

- The gateway **authenticates; it does not authorize.** It checks the access token on `/api/*` and answers 401 before git2 core. Whether a caller may see a resource is the service's decision; a hidden resource is 404.
- On `/api/*` the gateway forwards `Authorization` unchanged and **does not set `X-Git2-User-Id`.** Services verify the token again with `authsvc.RequireAuth` and read the caller with `authsvc.UserID(ctx)`.
- `X-Git2-User-Id` is set **on Git routes only**, where the client sends Basic credentials and git-svc never sees a token.
- `/api/setup/*` (first-admin setup, git2#18) is public like `/api/auth/*`; auth-svc checks the one-time setup token itself.
- The gateway strips client-sent `X-Git2-*`, `X-Real-IP` and `X-Forwarded-*` headers on every route.

## 🟡 CHANGED: Redis faults on the API check

The revoked and disabled checks fail open on a Redis fault, as in auth-svc (git2#14). v0 said 503. Signature and expiry are still checked.

## 🟡 CHANGED: Git route

- Upstream is git-svc Smart HTTP on `git-svc:9080`. `Content-Type`, `Content-Encoding` and `Git-Protocol` pass through; bodies stream without buffering.
- Basic auth with the git2 username and password. Inactive and disabled accounts get 401.
- v0 access rule: only the repository's owner. Anyone else gets 404 until repository roles and visibility exist.

## 🟢 NEW: response headers

Upstream response headers pass through unchanged. The gateway adds `X-Content-Type-Options: nosniff` to every response.

## 🟡 CHANGED: Compose has a gateway

- New service `gateway` (image `git2-gateway`, built from git2 with the Dash and Admin apps). It is the **only published port**: `GIT2_BIND` / `GIT2_HTTP_PORT` now publish the gateway, and `git2` has no host port.
- The Compose network has a fixed subnet, `GIT2_SUBNET` (default `172.31.250.0/24`). git2 core believes `X-Real-IP` only from it (`TRUSTED_PROXY_CIDRS`, git2#22).
- git-svc exposes `9080` (Smart HTTP) on the network, with a `/healthz` health check (needs git2-codeplane#5).
- Needs git2#21 and git2#22 merged; until then build from a branch with both (`GIT2_SRC=<checkout>`). Reference: [compose.md](../../../api/compose.md).
